## Observations for review (not decisions)

- **CESH device token.** The server accepts any registered UID without checking the device token the firmware sends. The [ingestion contract](ingestion-contract.md) already makes authentication an adoption prerequisite.
- **RKC handler checks.** [Alert-arming endpoints](https://github.com/bardphysicslab/rkc-monitor/blob/0c4f9238a7c85f282a69d92f4142c6eea06f184e/software/app/main.py#L3409) and [log download](https://github.com/bardphysicslab/rkc-monitor/blob/0c4f9238a7c85f282a69d92f4142c6eea06f184e/software/app/main.py#L3189) have no admin dependency in their handlers, and no Twilio signature validation was found in the SMS webhook. Network or proxy protection was not inspected, so this is not a statement about deployed exposure.
- **RKC incident state.** Active alert and acknowledgement state is held in memory.
- **Backup scope.** Registry-like data, contacts and configuration fall outside any backup scope found.
- **Personal data.** Retention and privacy rules for inbound SMS content, phone numbers and remote IPs are not defined.

## Deployment check (CESH backup, 2026-10-17)

Codex did a read-only check of the deployed CESH server; nothing was changed.
- The backup timer was active and recent runs succeeded.
- The installed script uses per-node catch-up deferrals.
- Retained logs show real deferrals on October 15 and 16 (runs skipping 67 and
  75 files).
- The deferral file held no nodes at inspection.
- Today's active daily CSVs are skipped.

Not covered by the check:
- no induced outage or catch-up test;
- no record-by-record comparison of local files with Drive;
- the deployed server's runtime handler (it uses an older repository layout).

These results do not prove every record reached Drive.

## Limits

Source evidence comes from repository files and safe examples at the pinned revisions. The only deployment evidence is the dated, scoped backup check above. The runtime upload handler, live configuration values and record-level Drive completeness remain unverified. An unlinked entry names a code area without a single anchoring line.
